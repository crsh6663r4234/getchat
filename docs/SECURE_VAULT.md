# Isolated SQLCipher vault (Phase 2 worktree)

`secure_vault::open_or_create(path, passphrase, os_secret).await` returns a SQLx pool only after SQLCipher 4 is present, the encrypted schema can be authenticated and the internal vault identity matches. The caller owns OS credential provisioning and must opt in explicitly. This is a new isolated database, never a migration or an automatic replacement for `ghostchat.sqlite`.

The path must be absolute with an existing parent. The manifest is `<database>.vault.json`. Both files must exist together or both must be absent. Existing ordinary SQLite files, missing/incomplete manifests, unexpected KDF parameters, symlinks and orphan journal/WAL files fail closed. First creation uses exclusive `create_new` file reservations and synchronized writes. Interrupted creation is deliberately blocked; it is not silently repaired. This does not provide a fully durable multi-file filesystem transaction or protect against a privileged local attacker racing directory operations.

A random 32-byte data encryption key encrypts SQLCipher pages. A separate AES-256-GCM wrapping key is derived from Argon2id v19 (65536 KiB, 3 iterations, 4 lanes, random 16-byte salt, 32-byte output), concatenated with the 32-byte OS secret, then HKDF-SHA256 with a separate random 16-byte salt and `GhostChat SQLCipher vault KEK v1` info. The wrapping nonce is random 12 bytes. Manifest version 1 records only public KDF metadata, vault UUID, nonce and authenticated wrapped key. Version, UUID and the canonical parent plus filename are authenticated as fixed-domain AAD. Moving a vault requires an explicit future rewrap operation; copying files to another path does not unlock them.

The module disables statement logging, requires SQLCipher version 4, applies the key before any SQLx database pragmas, enables page HMACs, zero plaintext header bytes, cipher memory security and in-memory temporary storage. Application-owned derived keys and raw-key encoding buffers are zeroized. SQLx retains its own raw key pragma string in pool connection options so reconnection remains possible; this is an explicit in-process memory limitation, not a promise that every library allocation is zeroized. Close the pool before releasing its OS credential lifecycle. The caller must not log environment values, passphrases, raw keys or connection options.

No identity recovery, historical ratchet restore, account export, backup portability, Shamir recovery or deletion proof is implemented by this module. Identity recovery must not silently recover historical message keys. Full database encryption complements existing field encryption; it does not replace transport E2EE or prevent server metadata visibility. SSD secure deletion cannot be proven.

Feature-gated tests exercise persisted reopen, wrong passphrase, wrong OS secret, corrupted encrypted page, plaintext rejection, orphan rejection and plaintext marker/header scans in both the database and live WAL. These are targeted storage checks, not a completed architecture audit. Run `cargo test -p ghostchat-desktop --features sqlcipher-vault secure_vault::tests` with the SQLCipher/OpenSSL build dependencies available. No successful execution is implied merely by these tests being present.

Protocol references: [SQLCipher API](https://www.zetetic.net/sqlcipher/sqlcipher-api/) and [SQLCipher design](https://www.zetetic.net/sqlcipher/design/). SQLx 0.8.6's SQLite options explicitly order the `key` pragma first; ordinary SQLite accepting an unknown pragma is never treated as proof of encryption.
